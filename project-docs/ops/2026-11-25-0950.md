# 2026-11-25 09:50 JST project-docs はデータのエクスポートから。運用者名を sanitize.py から外した

- 人間の判断: Project の文書は claude.ai の「データのエクスポート」の projects.json から取り出す（会話で 1 件ずつ読むと、小さい文書は打ち直しになり時間と写し間違いの心配があるため）
- 対象は人間側の文書だけ: `farm/phase*`・`farm/current/`・`farm/tools/`・`farm/publish/` はサーバーのパックにあるので除く。書き出し先は `project-docs/<farm/ を除いたパス>`
- 気づいた問題: `sanitize.py` のソースに置き換え対象の名前（ホスト名、GitHub ハンドル、法人名）が直接書いてあり、`tools/` に入れて公開するとそのファイル自体がハンドルと法人を結びつける
- 直したこと
  - `sanitize.py`: 運用者の名前は `--identities <TSV>`（`正規表現 TAB 置換 [TAB i]`、置換が `-` なら残りの検出だけ）から読む。ソースには名前を置かない。`--check-only`（変更せずに残りの検出だけ）を追加
  - `identities.tsv`: 名前の一覧。**サーバーの `~/tools/` にだけ置く。公開しない、Project にも置かない**。`<org>` 単体と `<org>` 単体を残りの検出に追加
  - `collect.sh`: `identities.tsv` がないと止まる。sanitize に `--identities` を渡す
  - 新規 `extract_project_docs.py`: projects.json からプロジェクト名で文書を探して書き出す（形が想定と違えばキーの一覧を出して止まる）
  - 新規 `add_project_docs.sh`: 取り出し → 秘密の値を集める → project-docs を伏せ字 → README と tools/ を置く（identities.tsv は置かない） → 木全体を `--check-only` でもう一度確かめる → 固め直す
  - `README.md`: tools/ の行に、名前は公開しない別ファイルから読む旨
- 次: 人間がエクスポートを依頼し、届いた zip の projects.json をサーバーに置いて `bash ~/tools/add_project_docs.sh <projects.json>`
