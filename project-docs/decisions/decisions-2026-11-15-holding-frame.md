# USDC で別の資産を買って持つ型に、合計 200 USD の枠を作った（人間、2026-11-15）

phase 12d で、gate と watchdog に「持ち高の枠」を足しました。役割ファイルへの反映も phase 12d で済ませてあります（meta は足し直さないでください）。

## 何ができるようになったか

今までは「1 つの tx の中で残高が増えなければ revert」に当てはまる bot しか live に出せませんでした。これからは、次の型も出せます。

> USDC を持って待つ → 機会が来たら USDC で別の資産を買う → しばらく持つ → 売って USDC に戻す

例: 割引で売られるもの（Dutch オークション、手数料や収益の入札）を買って、市場で売り戻す。買う tx と売る tx が別なので、その間は値下がりの危険を持ちます。その危険を、合計 200 USD までなら取ってよい、という決定です。

## 枠

- manifest に `holding_usd: <USD>` と書いた bot が対象です。別の資産で持ってよい上限です
- 1 本あたり **100 USD まで**、live の bot の合計で **200 USD まで**。超える promote は gate が資金を動かす前に断ります（止めかけで live に残っている bot も数えます）
- **最初の 1 本は `holding_usd` 20 程度**にしてください。USDC を持つ bot を止めて回収する流れは、実資金ではまだ一度も通っていません
- `principal_usdc` は `holding_usd` 以上にすること（買う元手は bot 自身の USDC です）
- `holding_max_hours` を書くこと。**最長 168（7 日）**。過ぎたら bot が自分で売って USDC に戻します

## 対象になる型、ならない型

- 対象: **同じチェーンの中で、いつでも 1 つの tx で USDC に戻せる**資産だけ
- 対象外: ブリッジをまたぐもの、ロックや償還の待ち時間があるもの、順番待ちやエポックの切り替わりを待つもの。待っている間に、別の理由で出口が閉じることがあるからです。これらは今までどおり lead に記録して止めてください
- チェーンをまたぐ型は、両方のチェーンに USDC を置いて、それぞれのチェーンの中で「買って売る」を完結させる形なら、この枠で扱えます
- 利回りを取りに預けるだけの型（貸し出し、流動性の提供）は、200 USD では 1 日数セントにしかなりません。枠は「割引で買って売る」型に使ってください

## executor の作り

- 買った資産は **executor に置きます**（bot の wallet には置かない）。「tx の終わりに executor に何も残さない」（decision 2026-11-15-executor-no-baked-targets）は、この枠の bot では「持ち高だけは残してよい」に変わります。承認（approve）を残さないこと、対象を焼き込まないことは変わりません
- **買う入口**: 払う USDC の上限と、受け取る資産の下限を引数に取ること。受け取った資産を、その場の出口のプールで売ったときに元が取れる水準でなければ revert すること
- **`exitAll()`**: 引数なし、owner（bot の wallet）だけが呼べること。持っている資産を全部売って、USDC を bot の wallet に送ること。何も持っていないときは revert せずに終わること。**いつ呼んでも** 1 つの tx で戻せること
- 普段の売りは、最低受取額の引数がある別の入口で行ってください。`exitAll()` は、gate が止めるときと、期限を過ぎたときのための出口です（gate は最低受取額を計算できないので、`exitAll()` は公開の mempool に下限なしで出ます）
- 出口のプールの厚みは、持ち高の 10 倍以上あること。小さなプール 1 つで値段が決まる資産は持たないこと
- bot は自分で売る値段（損切りの線）を持つこと。**持ち高の値段は、誰も見ていません**（下の「watchdog」）

## gate と watchdog がすること

- **gate promote**: 上の枠（1 本 100、合計 200、`principal_usdc`、`holding_max_hours`、executor の ABI に引数なしの `exitAll()` があること）を、資金を動かす前に確かめます
- **gate stop**: この枠の bot では、sweep の前に、bot の鍵で executor の `exitAll()` を呼びます。戻ってきた USDC を、今までどおり中間ウォレットに戻します
- **`exitAll()` が失敗したとき**（見積もりで revert、載らない、載って revert、executor に USDC が残っている）: 何も sweep せず、bot は live に残り、終了コード 3 で終わります。**ここから先は人間が決めます**。live-operator は `gate stop` をやり直さず、gate が出した `exit_failed` の行を inbox/human に書いてください。失敗した tx が 3 本たまると、gate はそれ以上 `exitAll()` を送りません
- **watchdog**: この枠の bot は、停止の線が **30 USD + `holding_usd`** になります（`holding_usd` 100 なら 130 USD）。USDC が executor に移って別の資産になった分を「なくなった」と数えないためです。持ち高の時価は見ません。つまり、**値下がりで止めるのは bot 自身の仕事**で、bot が何もしなければ `holding_usd` の全額を失うまで誰も止めません
- X（合計 2,000 USD）には、executor の中の持ち高は数えられません（最大 200 USD ぶん小さく見えます）

## 審査（paper-reviewer）

今までの条件のうち「残高が増えなければ revert」だけを、次に置き換えます。ほかの条件（読み取りの費用、期待収益の数え直し、反応時間、executor の形）は変わりません。

1. fork で、買う tx の成功と、値段が合わないときの revert を自分で再現する
2. fork で、`exitAll()` を「買った直後」と「時間を `holding_max_hours` より先に進めた後」の両方で呼び、どちらも 1 つの tx で USDC が bot の wallet に戻ること、executor に資産も USDC も残らないことを確かめる。owner 以外から呼ぶと revert することも確かめる
3. 出口のプールの厚みを測り、数字を review.md に書く（持ち高の 10 倍以上）
4. README に、最悪の損失（額と、何が起きたらそうなるか）が書いてある。上限は `holding_usd`
5. 期待収益は 1 往復ごとに「売って戻った額 − 買った額 − 2 本ぶんのガス代」で数える。損で終わった往復は、除かずにマイナスで数える
6. 出口に待ち時間があるものは fix ではなく demote（この枠の対象外）

## 変えないもの

- X・n・L（1 tx の最悪額 50 USD。買う tx のガス代はこの中）・bot あたり 400 USD
- `holding_usd` を書かない bot の扱いは、gate も watchdog も今までと同じです
- bot が USDC を executor に送ると、その額は 1 日の枠（`capital_usd`）に足されます。1 日に何往復もする bot は、`capital_usd` をそのぶん大きくするか、executor に USDC を承認して引き出させる形（その tx の中で使う額だけ承認し、0 に戻す）にしてください

## 人間の見立て

この類は、ブリッジをまたぐところまでやらないと大きくは儲からないと思っています。ただ、一部のチェーンで一時的に大きく安くなることはあるので、まずこの枠で始めます。結果を見て、枠と対象を見直します。
