# feed の導入と、速度勝負の線引きの変更（人間、2026-11-13）

phase 11a で `farm-feed`（`http://127.0.0.1:8546`）を入れました。bot はポーリングの代わりに、新しいブロックや指定したイベントを待てます。使い方は wiki `infra/feed.md`（meta が inbox/meta/2026-11-13-phase11a-feed.md から作ります）。

これに合わせて、decision 2026-11-12-morpho-stop-researcher-runs の 2（速度勝負のクラスはやらない）を次のように改めます。それ以外の項目はそのままです。

## 1. 線引き

きっかけ（価格更新、オークション開始など）から実際に取られるまでのブロック数で分けます。

- **同じブロック（0 ブロック）**: 速度勝負。今までどおり対象外で、`blocked_infra` と記録する
- **次のブロック（1 ブロック）**: feed で待つ bot なら試してよい。ただし同じブロックの中で競合より先に入る必要があり、勝てるかは未測定なので、**期待収益には数えない**
- **2 ブロック以上**: feed で待つ bot なら期待収益に数えてよい

ポーリングで待つ bot は今までどおりです（ポーリング間隔 + 取り込みまでの時間より短い事例は数えない）。

## 2. README の書き方（earner）

- 事例ごとの「取れる状態になってから取られるまでのブロック数と秒数」は今までどおり書く。feed を使う bot は、何を待つか（`/logs` のどのアドレス・どのイベントか）も書く
- 1 ブロックの事例は表に載せ、期待収益の合計からは外す。取れた・取れなかったの実績が live で出たら、その件数を書き足す
- CU の見積もりに feed の分を入れる: 1 日のイベント数 × 1 件のバイト数 × 0.04 CU。バイト数は推測せず、実際の log で測る（`http://127.0.0.1:8546/health` のフィルタごとの `cu_today` で確かめられる）
- feed が `gap`・429・503 を返したときに relay から読み直す処理と、数分おきの確認用のポーリングを必ず入れる

## 3. 審査（paper-reviewer）

- feed を使う bot は、`gap` と 429 / 503 のときに状態を読み直すことをコードで確かめる。なければ fix
- 期待収益は decision 2026-11-13-morpho3-stop-ev-net-of-gas の表から計算し直す。そのとき 0 ブロックと 1 ブロックの事例を除く
- 流量の多いイベント（トークンの Transfer、大きなプールの Swap など）を購読していたら fix

## 4. 変えないもの

- 送信の経路、L、bot あたり 400 USD、executor が利益なしで revert すること
- mempool の監視、バンドル、ビルダーへの直接送信はやりません。同じブロックで取る型は引き続き対象外です
- `/head`（毎ブロックの通知）は今は無効です。適用時の実測で ethereum の 1 ブロックが約 154 CU、1 日 約 1.1M CU かかり、ポーリングより高いためです。どのチェーンでも `/logs` で必要なイベントだけを待ってください
