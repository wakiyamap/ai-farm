# whype-gap-elysium の審査で確かめること、elysium への入金、ledger の source の整理（人間、2026-11-15）

11-15 19:19 JST のブリーフを読んで決めました。

## 1. elysium に入金します

持ち高の枠（decision 2026-11-15-holding-frame）の最初の 1 本として、whype-gap-elysium を試せるようにします。中間ウォレットの elysium に、USDC とガス用の HYPE を人間が入れます。入るまでは `gate promote` が資金不足で断ります。断られたら、reviewer は必要額を inbox/human に書いて、そこで止めてください（今までどおり）。

この 1 本は `holding_usd` 20 のままにしてください。額を上げるのは、止めて USDC が戻るところまで実資金で一度通ってからです。

## 2. whype-gap-elysium: promote の前に確かめること（paper-reviewer、earner）

枠の条件（decision 2026-11-15-holding-frame の「審査」）に加えて、この bot では次の 4 つを確かめてください。

### 2-1. 利益のうち、gap の戻りで説明できるのはいくらか

earner の測定は「100 USD で 1 日 11.6 USD、26.5 時間で 12 往復」で、1 往復あたり約 1% の純益です。一方、gap は −1% で入って −0.1% まで戻っても 0.9%、中央値の −0.86% までなら 0.14% しか動きません。差は、持っている間の HYPE そのものの値動きのはずです。

- earner: 測定の往復ごとに、損益を **「gap の変化のぶん」と「HYPE の値動きのぶん」に分けて** README の表に書いてください。入ったときと出たときの、プールの値段と参照の値段（HyperCore の現物）の両方があれば分けられます。損で終わった往復、損切りで終わった往復、24 時間の時間切れで終わった往復も、除かずに載せる
- paper-reviewer: この表から自分で計算し直してください。**期待収益として数えるのは gap のぶんだけ**です（そこからプールの手数料 2 回ぶんとガスを引く）。HYPE の値動きのぶんは、上がるか下がるか分からないので 0 と置きます
- gap のぶんだけで差し引きが 0 以下なら、promote せず、数字を review.md と inbox/human に書いてください。出すかどうかは人間が決めます（20 USD で出口の流れを試すだけ、という出し方はありえます）

### 2-2. その値引きは、戻る歪みか、定常の値引きか

中央値で −0.86% が続いているなら、それはこのプールのいつもの値段かもしれません（ブリッジの費用、プールの手数料、片側に寄った流動性など）。HyperEVM の同じペアは中央値 +0.08% でした。

- earner: gap の時系列から、−1% 以下になった回ごとに「−0.1% まで戻ったか、戻るまで何分か、戻らずに −0.86% 付近で止まったか」を数えて README に書いてください。出口の線（−0.1%）に届かない回が多いなら、出口の線を実際に届く水準に直し、2-1 の表もその線で作り直す
- 測定が 26.5 時間ぶんしかないことも README に書いてください。promote の後も paper と同じ記録を live のログに出し、3 日ぶんたまったら数え直して inbox/meta に書く

### 2-3. hook が売りを止められないこと

プール A には hook がついています（`0xc0ed888a…`。fork では、hook が読む `0x64` のコントラクトがないと swap が通らず、afterSwap で gasleft が 250k 以上ないと revert しました）。枠の条件は「いつ呼んでも 1 つの tx で USDC に戻せる」です。

- paper-reviewer: hook のコードを読み（検証済みのソースがなければ、その旨を review.md に書く）、次を確かめてください。誰かが hook の設定を変えて swap を止められるか（owner、pause、許可リスト、手数料の変更）。`0x64` が何で、mainnet で常にあるものか。gasleft の条件を `exitAll()` が必ず満たすか（gate は見積もりの 1.5 倍のガスで呼びます）
- 止められる権限を持つ誰かがいるなら、それを README の「最悪の損失」に「hook の owner が売りを止めた場合、持ち高の全額」と書いてあること。書いていなければ fix
- ソースが読めず、止められるかどうか分からないなら、promote せずに inbox/human に書いてください

### 2-4. 参照の値段が取れないとき

参照は Hyperliquid の API（チェーンの外）です。

- 取れない・古い（1 分以上前）・前の値から大きく飛んでいるときは、**買わない**こと
- そのときでも、持ち高の損切り（プールの値段だけで判定できる形にする）と、24 時間の時間切れの売りは動くこと
- paper-reviewer はコードで確かめ、なければ fix

## 3. ledger の sources.d の整理は、meta の提案どおりでよい

sources.d が 40 / 40 で、researcher の `add-source` が断られています。新しい区画を探してほしいのに記録する場所がないのは困るので、meta が提案した 5 件を外してください。条件は 2 つです。

- 外す前に、その source から作った lead が measured のまま残っていないこと、live と paper の bot の README がその source を根拠にしていないことを確かめる。当てはまるものは外さず、代わりの候補を inbox/human に出す
- 外す source の定義ファイルは消さずに、`ledger/sources.d` の外（`history/` など）に移す。取り込み済みの行は消さない

外したら、researcher が用意していた source（inbox/meta にある仕様）を足してください。今後も 40 に届いたら、同じ条件で meta が古いものから整理して構いません（そのつど、外したものを報告に書く）。
