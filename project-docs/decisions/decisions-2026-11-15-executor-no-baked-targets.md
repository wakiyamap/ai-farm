# executor に狙いを焼き込まない、準備の tx と approve を残さない（人間、2026-11-15）

morpho-nextblock-ethereum の最初の送信（プールの初期化）を見て決めました。inbox/meta 2026-11-15-morpho-nextblock-pool-init.md の規則（準備の tx は起動時に送る）を、下の 2 で改めます。

## 理由

farm は executor を promote の時に先に配備し、後から実行しています。配備された executor のコンストラクタの引数、storage、準備の tx（`setPoolAllowed` など）は誰でも読めます。こちらが crash-postmortem の 2-1 で相手のコントラクトを読んでいるのと同じことを、相手もできます。未検証でも、バイトコードとトレースから対象の市場や売却先のプールは分かります。

皆が見ている清算では大きな差になりませんが、単発の取り残しや、他の人が気づいていない機会では、先に「ここを狙っている」と教えることになります。常設の executor に approve や設定が残っていれば、そこを突かれる面にもなります。

## 1. 対象は呼び出しの引数で渡す

- 市場の ID、借り手、担保と債務のトークン、売却先のプール、換金の経路は、executor のコンストラクタの引数・storage・定数に入れず、実行の tx の引数で渡してください
- コンストラクタの引数は owner（`{bot}`）だけが基本です。プロトコル本体のアドレス（Morpho の本体、フラッシュローンの出し手など、どの市場でも同じもの）は定数でかまいません
- 安全の条件は今までどおりです。入口は owner だけが呼べる。利益がなければ revert する。利益は同じ tx の中でネイティブか USDC で bot の wallet に返す
- コールバック（swap のコールバック、フラッシュローンの受け取り、清算のコールバック）の呼び出し元は、許可リストを storage に持つ代わりに、owner が呼んだ入口で「今回の相手」を一時的に記録して照合し、tx の終わりに消してください。入口の外から直接コールバックを呼ばれたら revert すること

## 2. 準備の tx は作らない

- 配備の後に owner の tx（プールの許可、設定、approve など）が要る executor は作らないでください。配備と、機会が来た時の 1 tx だけで動く形にします
- どうしても準備の tx が要る場合だけ、11-15 の規則（live の起動時に全部送り、`executor armed` の行をログに出す）に従い、README に「なぜ要るか」を 1 行書いてください。reviewer は、引数で渡す形にできるのに準備の tx を残している bot を fix にしてください

## 3. approve と残高を残さない

- approve は実行の tx の中で、使う額だけを出し、終わりに 0 に戻してください。無期限・無制限の approve を executor から出さない
- tx の終わりに executor にトークンやネイティブが残らないこと。reviewer は fork の成功の tx の後で、executor の残高と、executor が出した approve が 0 であることを確かめてください

## 4. 単発の取り残しは、配備から最初の送信までを短くする

- 単発（`oneshot-…`）の bot は、live の起動の直後に最初の実行の tx を送る作りにしてください（次のポーリングまで待たない）
- reviewer は今までどおり次の回で先に審査します。promote してから最初の送信までに対象が消えていたら、それはそれで記録してください

## 5. 変えないもの

- executor は Solidity で書きます。Yul、Huff、手書きのバイトコードの executor は出さないでください。reviewer がソースを読んで「利益がなければ revert」と「引き出せるのは owner だけ」を確かめられることを優先します。読みにくくして隠す効果は小さく、相手は tx のトレースで動きを見ます
- executor のソースを公開の場に出さないでください（エクスプローラの verify、公開のリポジトリなど）
- 配備と実行を 1 tx にまとめる形（作成 tx の中で実行する）は、signer と gate の変更が要るので、人間が後で作ります。それまで bot から作成 tx を送ろうとしないでください（signer が拒否します）
- 今 live の 3 本は変えません。新しく出す bot と、fix で戻ってきた bot から適用します
