# 非公開の送信を ethereum で使えるようにした（人間、2026-11-15）

phase 12b（11-15 13:28 JST）で、公開の mempool を通さない送信の経路を足しました。役割ファイルへの反映は phase 12c で済ませてあります（meta は足し直さないでください）。

## 何ができるようになったか

- manifest に `send_route: private` と書いた bot の tx は、**ethereum でだけ**、Flashbots Protect を通ってブロックのビルダーに直接渡ります。公開の mempool には出ません。経路が失敗しても公開には出さず、その tx は捨てられます
- ほかのチェーンでは、このキーを書いても今までどおり Alchemy から公開で送られます
- 書かなければ（または `public` なら）、今までと何も変わりません

## 何のために使うか

1. 公開の mempool に出すと真似される・先に取られる機会を取る
2. 外したときの費用をなくす。revert する tx はブロックに載らないので、ガスがかかりません

**これで皆が見ている清算が取れるようにはなりません。** 11-14 の lead 14 の実測では、取り手は粗利 約 7,523 USD に対して、4.014 ETH（約 7,570 USD）をブロックのビルダーに払っていました。粗利のほぼ全額です。そういう入札はしませんし、executor からビルダーに払うこと（`block.coinbase` への送金）も作りません。競争の薄い機会に使ってください。

## 条件

- executor の入口に期限（ブロック番号）の引数を持たせ、過ぎていたら revert させること。期限は 2〜3 ブロック先。fork で「期限を過ぎたら revert」を再現すること
- 非公開の tx は、載らなくても誰も知らせてくれません。bot は送った後、期限まで receipt を見て、なければ `private_not_included` をログに出すこと
- 前の非公開の tx が載る前にもう 1 本送ると、同じ nonce になり、前の tx を置き換えます（載るのはどちらか 1 本）
- 送るたびに、その tx の最悪額が 1 日の枠（`capital_usd`）に足されます。載らなくても枠は減ります
- README に、なぜ非公開にするかを 1 行で書くこと
- mempool の監視はしません。他人の tx の前後に入ることもしません（S は変わりません）。X・n・L・bot あたり 400 USD・累計損失 30 USD の停止も変わりません

## まだ確かめていないこと

実際の tx がこの経路で載ること、載るまでのブロック数、revert する tx が本当に載らないことは、まだ実資金で確かめていません。最初にこの経路を使う bot の最初の送信で確かめます。その bot の reviewer と earner は、最初の送信の結果（載ったか、何ブロック後か、載らなかったか）を inbox/meta に書いてください。
