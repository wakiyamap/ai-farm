# チェーンをまたぐ値段の差を測る: 経路は Relay（人間、2026-11-15）

今日の測定で、elysium の WHYPE は HyperCore の現物より 0.86〜1.36% 安い状態が続き（lead 184）、HyperEVM の同じペアは中央値で +0.08% でした（attempts の whype-gap-hyperevm）。同じチェーンの中で戻りを待つ型は閉じましたが、**2 つのチェーンの間の差そのものは残っています**。これを、運ぶ費用まで入れて測ってください。

これは人間から出す候補です。「候補は人間から出さない」（11-04）は変えませんが、この 1 件は例外として挙げます。人間の見立て: bot の本領は裁定で、今はブリッジを通さないと厳しい。

## 1. 経路は Relay を使って測る

運ぶ経路は Relay（https://www.relay.link/ 、API は `https://api.relay.link`、説明は https://docs.relay.link ）をまず調べてください。ソルバーが相手側のチェーンで先に払い出す型で、見積もりに費用が全部入って返ります。**スリッページに気をつけること**（人間の注意）: 見積もりの額ではなく、最低受取額で数えてください。

**elysium は Relay で使えます。** 11-15 21 時ごろ、人間が中間ウォレットの資金を Relay で ethereum から elysium に運びました。実績: ethereum の USDC が 205.00 減り、elysium に USDC 199.96 と HYPE 約 5.01 USD ぶんが着いた（合わせて約 204.97 USD。差は約 0.03 USD = 0.015% 程度。ほかに ethereum 側のガス）。USDC を運ぶ費用は、WHYPE の差（1% 前後）に比べてずっと小さいということです。残る問いは、WHYPE / HYPE の側の経路と厚み、それと 1 周を通したときの差し引きです。

## 2. 測定の依頼（earner の measure のレーン。researcher が先に手を付けてもよい）

**tx は 1 本も送りません。見積もりと読み取りだけです。**

1. `GET https://api.relay.link/chains` で、elysium（chain id 99901）と hyperevm（999）について、扱う通貨（USDC、HYPE / WHYPE）と、Relay のコントラクトのアドレス（depository、router、approval proxy など）を記録する。elysium が使えることは上の実績で分かっている。通貨の一覧に WHYPE も HYPE もなければ、USDC だけを Relay で運び、WHYPE は両側のプールで売り買いする回り方で数える
2. `POST https://api.relay.link/quote/v2` で見積もりを取る。API キーを求められたら（401 など）、そこで止めて inbox/human に書く（キーは人間が判断します）。`user` と `recipient` は適当な自分のアドレスで構いません（見積もりだけなので資金は要らない）。取る組:
   - elysium の USDC → hyperevm の USDC、その逆
   - elysium の WHYPE → hyperevm の HYPE（または WHYPE）、その逆
   - elysium の USDC → hyperevm の WHYPE のように、運ぶのと換えるのを Relay に任せる形
   - 額は 20 / 50 / 100 / 200 USD 相当の 4 つ
   - 照らし合わせ: ethereum の USDC → elysium の USDC を 200 USD で見積もり、上の実績（約 0.015%）と合うかを見る。大きくずれるなら、見積もりの読み方がどこか違う
3. 見積もりごとに記録する: 受け取る額、最低受取額（スリッページの設定つき。設定の名前と既定の値も）、費用の内訳（ガス、ソルバー、プラットフォーム、swap の値段の影響）、所要時間の見込み、見積もりの有効期限
4. **1 周の差し引きを数える**。出発は elysium の USDC。たとえば「elysium のプールで WHYPE を買う → Relay で hyperevm に運ぶ → hyperevm のプールで USDC に売る → Relay で USDC を elysium に戻す」。ほかの回り方（Relay に換えるところまで任せる形）も比べる。**差し引き = 戻ってきた USDC の最低受取額 − 出した USDC − 両側のガス**。額ごとに出す
5. これを 10 分おきに 24 時間ぶん取り、プラスになった回数、中央値、最大、プラスが続いた時間を出す。lead 184 の系列（プール A の値段）と同じ時刻で並べる
6. 実行の形を調べる（送らずに、見積もりの `steps` を読む）: 利用者が送る tx の宛先と calldata の形、approve が要るか、ソルバーが払い出さなかったときの返金（いつ、どこに戻るか）、状態を確かめる口（`/intents/status`）。bot の wallet は全チェーンで同じアドレスなので、受取先を自分の wallet にできるかも確かめる
7. 信用の置き方: 誰が払い出すのか、払い出されないまま資金が止まることがあるか、上限。docs の security のページと、実際に最近の他人の取引（`/requests`）で「見積もりの費用」と「実際の費用」がどれだけずれたかを見る

結果は lead として記録し（status は測定の結果どおり）、inbox/meta に要約を書いてください。

## 3. bot はまだ作らない

持ち高の枠（decision 2026-11-15-holding-frame）は、ブリッジをまたぐ型を対象外にしています。運んでいる途中の資金を gate と watchdog がどう数えるか、途中で止めたときにどう回収するかが、まだ作られていないためです。

- 2 の差し引きが、20 USD の額でガスを引いてもプラスの回が 1 日に数回以上あるなら、meta が数字を inbox/human に回してください。人間が仕組み（運んでいる資金の枠）を作ります
- マイナスなら、差の原因は運ぶ費用そのものだと分かります。lead にそう書いて閉じ、同じ測り方を次の組に回してください

## 4. ほかの組

elysium と hyperevm の測定が済んだら、同じ測り方で、farm のチェーンの間で値段の差が続いている同じ資産の組を探してください（Relay の `/chains` に載っているチェーンと通貨が出発点です）。見つけたら、1 つずつ測定の依頼の形で lead にする。数を並べるより、差が 1 日以上続いているものを 1 つ確かめるほうを先に。
